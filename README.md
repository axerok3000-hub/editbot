# editbot

Telegram Business Bot: анимирует эффект печатной машинки для твоих
собственных исходящих сообщений и уведомляет тебя, если собеседник
удалил или отредактировал своё сообщение.

Бот не отвечает и не пишет от своего имени в чужие чаты — он молча
подключается к твоему аккаунту как Business Bot, следит за твоими
исходящими и за сообщениями собеседников, и обо всём важном пишет
тебе лично.

## Как это работает

1. Ты подключаешь бота в Telegram: **Settings → Telegram Business → Chatbots**.
   Бот получает апдейт `business_connection` — сохраняет `business_connection_id`
   и id владельца аккаунта.
2. Ты пишешь в любом личном чате сообщение с суффиксом `.p`, например:
   `Привет.p`
3. Бот ловит апдейт `business_message`, видит, что отправитель — владелец
   подключения, и что текст оканчивается на `.p`.
4. Через `edit_message_text` (с `business_connection_id`) бот постепенно
   дописывает текст — получается эффект печати. В конце в чате остаётся
   текст без суффикса: `Привет`. Скорость подстраивается под длину текста
   (см. `bot/typewriter.py`): до 20 символов — посимвольно, до 120 — не
   более 18 шагов, длиннее — без анимации плюс предупреждение тебе в личку.

Сообщения без суффикса `.p` от тебя, а также чаты из списка исключений
(управляются кнопкой «🚫 Исключения» в `/start`), анимацией не
затрагиваются.

## Анти-удаление

Бот кэширует входящие сообщения собеседника (текст и медиа — фото,
видео, голосовые, документы) в локальную SQLite-базу (`bot/db.py`,
таблица `cached`). Твои собственные сообщения (в том числе технические
правки от анимации печати) не кэшируются.

- **Удаление**: апдейт `deleted_business_messages` содержит только id
  удалённых сообщений — бот достаёт их из кэша и присылает тебе в личку
  отправителя, чат, время и содержимое. Если это медиа — пересылает по
  `file_id`; если `file_id` уже протух, шлёт текст с пометкой
  «медиа недоступно».
- **Редактирование**: апдейт `edited_business_message` от собеседника
  присылает тебе «было / стало». Правки твоих собственных сообщений
  (включая посимвольные правки анимации печати) не репортятся — иначе
  каждый `.p` заспамил бы тебе личку.
- **Очистка**: раз в час бот удаляет из кэша записи старше
  `CACHE_RETENTION_DAYS` (по умолчанию 7 дней).
- Кнопка «🗑 Мои удалённые» в `/start` показывает последние 10 удалённых
  сообщений.

## Стиль текста

Кнопка «🎨 Стиль» в `/start` открывает инлайн-меню: Обычный, Жирный,
Курсив, Зачёркнутый, Моноширинный, Готический, Курсивный юникод.
Текущий стиль отмечен 🔵, остальные 🔴; выбор сохраняется в SQLite
(таблица `settings`, `bot/db.py`).

Жирный/курсив/зачёркнутый/моноширинный делаются через `parse_mode=HTML`
(`<b>`, `<i>`, `<s>`, `<code>`) — работают на любом языке, включая
кириллицу. Готический и курсивный юникод — через таблицу подстановки
символов в `bot/fonts.py`: у Unicode просто нет отдельных
готических/курсивных букв для кириллицы (в отличие от латиницы), так
что для ~19 кириллических букв, похожих по начертанию на латинские
(а, е, о, р, с, у, х и их заглавные пары и т.п.), применяется стиль
через похожую латинскую букву; остальные ~20 букв (б, г, д, ж, з, и...)
остаются обычными — так что вид получается частично стилизованным.

Применяется к твоим исходящим сообщениям **без** суффикса `.p`
(суффикс `.p` всегда имеет приоритет — запускает анимацию печати вместо
стиля) одним `edit_message_text` на сообщение. Из-за этого при активной
переписке легко упереться в лимиты Telegram на редактирование, поэтому:

- бот сам ограничивает себя одним edit на чат раз в 0.5 сек (лишние
  правки в этом окне просто пропускаются, без ошибок);
- если Telegram всё равно ответит `TelegramRetryAfter`, бот **автоматически
  переключает стиль на «Обычный»** и пишет тебе в личку, что стиль
  отключён и его нужно включить заново через меню.

## Команды и меню

Единственная текстовая команда — `/start` в личном чате с самим ботом
(не через business, а напрямую). Всё остальное — через инлайн-кнопки:

- «👤 Профиль» / «🔗 Соединение» — статус подключения
- «🎨 Стиль» — выбор стиля исходящих сообщений (см. выше)
- «🚫 Исключения» — список чатов, которые бот когда-либо видел
  (`bot/db.py`, таблица `known_chats`), с переключателем ✅/🚫 на каждый
  — тап переключает, эффект печати в 🚫-чатах отключается (на
  анти-удаление и стиль не влияет)
- «🗑 Мои удалённые» — последние 10 удалённых сообщений
- «✨ Эффекты» — справка про `.p` с моноширинным примером, который
  можно тапнуть и скопировать
- «🎮 Игры» — заглушка

Реагирует на всё это только `OWNER_ID` — все остальные отправители
молча игнорируются.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`:

```
BOT_TOKEN=<токен от @BotFather>
OWNER_ID=<твой Telegram user_id>
```

Узнать свой `user_id` можно, например, у [@userinfobot](https://t.me/userinfobot).
Остальные параметры (`TYPEWRITER_SUFFIX`, `CONNECTIONS_FILE`,
`EXCLUDED_CHATS_FILE`, `CACHE_DB_FILE`, `CACHE_RETENTION_DAYS`) можно
оставить по умолчанию.

## Подключение бота как Business Bot

1. Создай бота через [@BotFather](https://t.me/BotFather), если ещё нет.
2. В Telegram: **Settings → Telegram Business → Chatbots** → выбери своего
   бота.
3. Включи право читать сообщения ("Reply to messages" не обязательно, но
   должно быть включено "Can read messages" — иначе бот не увидит текст
   входящих `business_message`, а без этого не сработает и распознавание
   твоих собственных исходящих сообщений).

## Запуск

```bash
python main.py
```

Бот работает через long polling — процесс должен быть постоянно запущен
(systemd, screen/tmux, Docker и т.п.).

## Деплой на Railway

Бот — фоновый воркер (long polling), HTTP-порт не нужен. Всё делается через
веб-интерфейс Railway, можно с телефона.

1. Зайди на [railway.app](https://railway.app) → **New Project** →
   **Deploy from GitHub repo** → выбери `axerok3000-hub/editbot`
   (ветку `claude/telegram-typewriter-bot-melhq5`, или замерджи её в main).
2. Railway распознает `railway.json`/`Procfile` и сам поставит команду
   запуска `python main.py`. Порт открывать не нужно — сервис фоновый.
3. Открой сервис → **Variables** → добавь:
   - `BOT_TOKEN` — токен от @BotFather
   - `OWNER_ID` — твой Telegram user_id
   - `CONNECTIONS_FILE` = `/data/connections.json`
   - `EXCLUDED_CHATS_FILE` = `/data/excluded_chats.json`
   - `CACHE_DB_FILE` = `/data/cache.db`
4. Добавь постоянное хранилище: сервис → **Settings → Volumes** →
   **New Volume**, mount path `/data`. Это важно: без volume все эти
   файлы будут стираться при каждом передеплое — бот "забудет" про
   business-подключение и кэш сообщений для анти-удаления.
5. **Deploy**. В логах сервиса должно появиться `Start polling`.
6. Подключи бота в Telegram как Business Bot (см. раздел выше) — придёт
   апдейт `business_connection`, бот сохранит его в `/data/connections.json`.

Обновления кода: просто пушь в подключённую ветку — Railway передеплоит
автоматически.

## Структура

```
main.py                        точка входа, long polling, часовая очистка кэша
bot/config.py                   загрузка настроек из .env
bot/storage.py                   хранение business-подключений и списка исключений
bot/db.py                        SQLite: cached (анти-удаление) и settings (стиль)
bot/fonts.py                     таблицы подстановки символов (готика, курсивный юникод)
bot/styles.py                    рендер текста под выбранный стиль
bot/style_apply.py               edit_message_text со стилем: троттлинг + авто-выключение
bot/typewriter.py                адаптивная анимация печати через edit_message_text
bot/handlers/business.py         business_connection и business_message (печать/стиль/кэш)
bot/handlers/antidelete.py       deleted_business_messages и edited_business_message
bot/handlers/style.py            инлайн-меню выбора стиля (только OWNER_ID)
bot/handlers/commands.py         /start и все инлайн-меню (только OWNER_ID)
bot/handlers/filters.py          общий фильтр IsOwner
```
